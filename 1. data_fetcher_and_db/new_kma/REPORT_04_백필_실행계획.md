## 3. 실행 명령 (서버, resume-skip 로 밤마다 창 확장)

`--backfill N` = 오늘부터 과거 N일, **이미 완전한 base 는 fetch 없이 건너뜀**(auto-resume).
그래서 밤마다 N 을 넓혀 가면 매일 ~30 base 씩 새로 받고 나머지는 값싸게 확인만 한다.
격리 DB(`data/v2_*.db`)에 그대로 확장 적재 — 본 DB·서빙 무영향(컷오버는 별건).

```bash
cd ~/project2026/1.\ data_fetcher_and_db      # 서버 경로

# 전체 A (권장: 한 번 받아두면 모든 후속 EDA 재사용, 창구 닫히기 전 확보)
# 밤마다 1줄씩 (운영 cron 창 01~06시 밖에서)
python core/collect_forecast_v2.py --backfill 30  --region both   # 1일차: 최근 30 base
python core/collect_forecast_v2.py --backfill 60  --region both   # 2일차: 31~60
python core/collect_forecast_v2.py --backfill 90  --region both   # 3일차
python core/collect_forecast_v2.py --backfill 120 --region both   # 4일차
python core/collect_forecast_v2.py --backfill 146 --region both   # 5일차: 02-09 개시일까지
python core/collect_forecast_v2.py --verify --region both         # 완전성 확인(fetch 0)

# lean B (빠른 결과: 신재생/급변동 D+1~5 만) — NE57 생략은 --days 로 근지평 한정
python core/collect_forecast_v2.py --backfill 146 --region both --days 5
#   R030 는 어차피 120h(D+5) 상한, --days 5 면 NE57 도 D+5 까지만(콜 1/3)

# L010 국지(옵션, 초단기 신재생) — 별도 CLI
python core/collect_l010_archive.py --backfill 146 --region both
```

주의:
- 밤 시간대(자정 전후 KST) KMA 혼잡이 낮 대비 10배+ (제주 로그 grib 200초 콜드스타트 목격) — 새벽~오전 권장.
- 429/혼잡으로 일부 base 가 미완이면 다음 밤 같은 명령이 그 base 만 재수집(resume-skip).
- frcc(1h 운량)는 백필에 넣지 말 것(콜당 60~113초). 운량 EDA 가 필요해지면 `backfill_frcc_cols.py` 를 한가한 시간에 별도로.
- 이 백필은 **격리 DB 적재만** — 본 DB 컷오버(서빙 전환)와 무관. 컷오버 절차는 `REPORT_forecast_v2.md` §4.

## 3-보강. 자동 백필 cron (하루 ~5만콜 상한, 2026-07-05 추가)

`--max-bases N` 신설로 **같은 cron 한 줄을 매일 돌려도 실행당 N개 base 만** 받고 나머지는
다음 실행에서 이어받는다(resume-skip). base 하나 ≈ 1,743콜(육지+제주, ACSWDNB 포함, frcc·L010 제외)이므로
**N=33 ≈ 5.7만콜/일**. 운영 수집(~1.5만)과 합쳐 **~6만콜**(4키 풀 8만 대비 ~2만 여유 — gascast 운영
수집이 굶지 않게 8만을 다 쓰지 않는다). 약 5일이면 146 base 완료, 이후 실행은 전부 skip(콜 0)=자동 정지.

```cron
# 자동 백필 (격리 DB, 서빙 무영향). deploy/crontab.example 의 "(준비됨/선택) 자동 백필" 블록 참고.
# 07:30 = 운영 수집창(01:30~05:30)·서빙(06~07시)·자정 KMA 혼잡을 모두 피함.
# --production 금지(격리 DB). 로그는 wrapper 가 deploy/logs/ 에 남김(별도 리다이렉트 불필요).
30 7 * * * /home/USER/project2026/deploy/run_collect_forecast_v2.sh --backfill 146 --region both --max-bases 33
```

안전 요건(전부 충족 시 위험 낮음):
- **격리 DB 전용**: `--production` 없음 → data/v2_*.db 에만 적재, 서빙·운영 DB 무접촉.
- **상한**: `--max-bases 33` 로 하루 ~5.7만콜 → 운영 수집 합산 ~6만, 4키 풀(8만)에 ~2만 여유(gascast 보호).
- **시간대**: 07:30(운영 수집창·서빙·자정 혼잡 밖, 낮 KMA 한산). 백필 1회 ~2–3시간(33 base × ~4.7분).
- **수렴 후 자동 정지**: 전부 완결되면 collected=0 → 콜 0. 무한 재수집 없음.
- **주의**: base 는 오래된 것부터(oldest-first) 채운다 → 최근일 v2 는 마지막 실행에서 채워짐(백필 목적상 무방).

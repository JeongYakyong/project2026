# REPORT 03 — 전환 가능성 판단과 로드맵

> 근거: REPORT_01(정책 요약)·REPORT_02(프로브 결과)·nb01~nb04

## 1. 판단표 (go / no-go)

| 판단 항목 | 실측 결과 | 판정 |
|---|---|---|
| ① 장지평 D+13~15 소실 | 전구 신모델 최대 288h(D+12) 확정, 336/372h 없음. 현행 운영이 이미 D+12 라 **추가 손실 없음** | **수용** |
| ② backfill 깊이 | 개시일부터 전량·결측 0 (지역·국지 145일 — 봄~여름 포함). 개시일 이전은 없음 | **수용**(단, 1년 미만 — 겨울 데이터는 앞으로 쌓아야 함) |
| ③ 전운량 부재(지역·국지) | 단일면 운량 미탑재 확정. 기본 = 전구 병합 유지(현행 구조). ★추가 연구(nb05): **등압면 frcc 결합으로 1h 전운량+층별 운량 확보 가능**(구 grib ef 범위, 지점당 2콜, 자체 일사와 정합 검증) | **수용**(기본=전구 병합, 1h 필요 시 frcc 결합) |
| ④ 일사 단위·누적 처리 | GHI = SWDDIR2+SWDDIF2 (순시 W/m²) → 현행 ×0.0036 그대로. ACSWDNB 는 diff 패턴 재사용 | **수용** |
| ⑤ 격자 재매핑 값 점프 | 제주: 구 KIMR = 신 R030 동일 격자·값 완전 일치(0.005) → **시계열 단절 없음**. 육지 지역·국지는 신규 추가라 단절 개념 자체가 없음 | **수용** |
| ⑥ 신 std API 품질 | **격자 방식(xy_txt2_std)**: 전구 화면고도 8변수 위치 불변 버그 + 멀티변수 미지원 → 보류. ★**위경도 방식(pt_txt2_std, 문서 2.2.2)**: 버그 없음·멀티변수·등압면 전 레벨 1콜 — 정상 | **pt_txt2_std 채택 가능** (구 pt 와 동급 + 신세대) |

**종합 판단: "전면 교체"가 아니라 "현행 유지 + 확장 도입"이 정답이다.**

핵심 근거 — 이번 연구의 두 발견이 판을 갈랐다:
1. 현행 수집기는 **이미 신모델을 읽고 있다** (전구 NE57 · 제주 KIMR=r030). 07-01 이후에도 정상 동작 중.
   "구모델→신모델 전환" 작업은 애초에 필요가 없었다.
2. **구 pt 엔드포인트가 신모델 3종을 모두 지원** (위경도 직접 + 멀티변수 1콜). 검증된 기존 수집
   엔진에서 `group/nwp/name` 만 바꾸면 지역·국지 확장이 끝난다. 신 std API 는 버그(전구)와
   비효율(변수당 1콜) 때문에 지금은 채택하지 않는다.

## 2. 제안 아키텍처 — 사용자 구상("단기=국지, 중장기=지역+전구")의 구체화

```
지평       D+1        D+2        D+3~5      D+6~12
육지     [L010 1h]  [L010 1h]  [R030 1h]  [NE57 3h]     ← 신규 계층(제안)
          └─ 현행: NE57 3h + 보간 (그대로 두고 위를 "추가")
제주     [R030 1h D+1~5 = 현행 KIMR 그대로]  [NE57 3h]  ← 이미 이 구조!
운량     [NE57 tcld/mcld/lcld 3h — 전 지평 공통(기본)]
          └─ D+1~5 는 R030 frcc 결합(1h 전운량+층별, 지점당 2콜)로 대체·보강 가능 (nb05)
```

- **제주는 이미 목표 구조다** (KIMR 1h D+5 + KIMG 3h). 남는 개선 = 일사를 SWDDIR2/SWDDIF2 로
  받아 직달·산란 분리 입력을 추가하는 것 정도.
- **육지가 진짜 수혜자다**: 지금은 전구 3h(+보간)뿐인데, R030 1h(D+5)·L010 1h(D+2)를 얹으면
  단중기 기상 입력의 해상도가 3 km/1h 로 올라간다. 특히 07-01 부로 잃은 1h 해상도를 지역·국지가 되찾아준다.
- 신규 확보 가능한 피처: 허브고도 바람 U140/U220(풍력), 직달/산란/법선 일사(태양광), TSKIN·PBLH.

일일 콜 비용 견적 (구 pt 멀티변수 1콜 기준, 12z 1회):

| 수집 | 계산 | 콜/일 |
|---|---|---|
| 현행 전량 (변화 없음) | 육지 5지점×96hf + 제주 등 | 약 600~700 |
| + R030 1h D+1~5, 육지 5지점 | 120 hf × 5 | +600 |
| + L010 1h D+1~2, 육지 5지점 | 48 hf × 5 | +240 |
| + 제주 일사 확장(솔라팜 1지점) | 120 hf × 1 | +120 |
| **합계** | | **약 1,600~1,700 / 일 (쿼터 약 2만의 8%)** |

## 3. 백필·재훈련 데이터 전략

- **R030/L010 지평 아카이브 백필**: 2026-02-09 부터 전량 가능(결측 0, hf 꼬리·4주기 보존).
  12z 만 받으면 145일 × (120+48)hf × 5지점 ≈ 12만 콜 → 일 쿼터를 고려해 **7~10일 분할**(하루 1.5만 콜 이하).
- **전구 1h 과거 파일(glob_sfc)**: 구 pt 로 06-30 까지 조회 가능 — 언제 닫힐지 보장이 없으므로,
  필요하면(1h 학습데이터 보존 가치) **이 백필을 최우선으로** 서두를 것. 대상을 좁히면(제주 3지점 D+1~5,
  최근 1년) 하루 쿼터 안에서 며칠이면 된다.
- 재훈련 필요성: 기존 모델은 그대로 서빙 가능(입력 소스 불변). 신규 1h/신변수 피처를 **쓰기로
  결정할 때만** 해당 단계 재훈련이 필요하다. 피처 확정은 규율대로 EDA 후 사용자 확인(§0.6).

## 4. 리스크와 감시 항목

| 리스크 | 내용 | 대응 |
|---|---|---|
| 구 pt 폐지 가능성 | 정책 방향이 신 std 이관이면 구 pt 가 닫힐 수 있음 | ★해소에 가까움 — **`nph-kim_nc_pt_txt2_std`(2.2.2 임의 위경도)가 구 pt 와 동급 기능(위경도·멀티변수·정상 디코더)+등압면 전 레벨 1콜**임을 확인. 갈아탈 곳이 이미 있다. 격자 방식(xy) 버그는 **KMA 신고 권장** |
| R030 120h 축소 | 문서 스펙은 87h — 실측 120h 가 조정될 가능성 | 수집기에 "hf 상한 실패 시 자동 축소" 로직(현행 완결성 skip 이 이미 유사 동작) |
| glob_sfc 백필 창구 마감 | 과거 1h 전구 파일이 언제 지워질지 모름 | 백필 가치 판단을 빨리 — 사용자 결정 필요 |
| 신 std 버그의 파급 | KMA 가 신 std 를 고치면서 파일 체계를 또 바꿀 수 있음 | 월 1회 수준의 스모크 프로브(probe_lib 재사용, 수십 콜) |

## 5. 로드맵 (단계별, 각각 Decision Gate 후보)

| 단계 | 내용 | 상태 |
|---|---|---|
| 0 | **지금은 아무것도 바꾸지 않는다** — 현행 수집·서빙은 신모델 기준으로 이미 정상 | 완료(이번 연구로 확인) |

**요약 한 줄**: 07-01 변경으로 우리가 잃은 것은 이미 잃었고(전구 1h·D+13~15), 시스템은 신모델 위에서
정상이다. 이제 남은 것은 손실 복구가 아니라 **지역(3km/1h)·국지(1.3km/1h)라는 새 자원을 단중기
지평에 얹는 확장**이며, 그 통로(구 pt 멀티변수)와 데이터(개시일부터 전량 백필)가 모두 열려 있음을
실측으로 확인했다.
